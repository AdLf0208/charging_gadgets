Generated by `tools/assemble_content.py` from the ATM10 jar
`ports/_shared/licence-cache/charginggadgets-1.14.1.jar` (SHA-1 `3208ea2c…b357`;
provenance in
[`../_shared/carry-work/charginggadgets/SOURCE.md`](../_shared/carry-work/charginggadgets/SOURCE.md)).

`ports/_shared/evidence/charginggadgets/retired-hnmod-0.1.0/tools/assemble_content.py`;
run from the port root it still deletes `assets/` and `data/` first and rebuilds
them, and the SDK package carries those two trees **unchanged** at its root.

## Written here (decisions, not upstream files)

| File | What and why |
|---|---|
| `horizon-mod.toml` (port root) | the package manifest: id `charginggadgets`, API 0.2, `side = both`, `registries`, and `[native]` pinned to the SDK build |
| `assets/charginggadgets/items/charging_station.json` | 26.3's item model definition pointing at `charginggadgets:item/charging_station` |
| `data/charginggadgets/horizon/block/charging_station.json` | template **`minecraft:stonecutter`**: vanilla's only template with exactly one 4-value `facing` state whose class opens a menu on use (a mod container's menu needs that). | `data/charginggadgets/horizon/menu/charging_station_menu.json` | `{"slots": 2, "data_slots": 4}`, the container and data the native half's `ModContainer` names |

| `data/c/tags/item/{gems/lapis,gems/diamond,ingots/iron,storage_blocks/coal,dusts/redstone}.json` | the convention tags the jar's recipe and advancement name; the prepared 26.3 root ships none, and an unknown tag expands to an empty ingredient |

## Deliberately not carried

- The **`charginggadgets:energy` data component** and upstream's item-group code:
  the charge lives in the item-energy buffer the native half declares, and the
  tab is a content file above.
- The **GUI texture drawing** (carried for later use, not referenced).
- **`pack.mcmeta`** and the jar's `META-INF`: not content.
